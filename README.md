# Operation Server

Серверная часть учебного веб-приложения для работы с пользователями, тестами, вопросами, оценками и учебными материалами.

Проект реализует HTTP-сервер на чистой Java без Spring и других серверных фреймворков. Сервер самостоятельно принимает TCP-соединения, разбирает HTTP-запросы, маршрутизирует их по URL и HTTP-методу и передаёт обработку специализированным servlet-классам.

## Возможности

- регистрация и работа с пользователями;
- авторизация пользователя;
- работа с тестами и вопросами;
- получение и сохранение оценок;
- работа с книгами и тематиками;
- HTTP API с отдельными обработчиками запросов;
- хранение данных в PostgreSQL;
- автоматическая инициализация структуры базы данных и начальных данных;
- запуск приложения и PostgreSQL в Docker.

## Архитектура

Основная часть сервера разделена на несколько уровней:

```text
Client
   │
   ▼
Server
   │
   ▼
RequestHandler
   │
   ▼
RequestDispatcher
   │
   ├── Servlet
   ├── Request
   └── Response
        │
        ▼
     Database
        │
        ▼
     PostgreSQL
```

### HTTP-сервер

`Server` работает поверх `ServerSocket` и принимает входящие TCP-соединения. Для обработки подключения создаётся отдельный поток.

`RequestHandler` отвечает за обработку соединения и преобразование входящего HTTP-запроса в объект `Request`.

`RequestDispatcher` определяет, какой servlet должен обработать запрос, исходя из URL и HTTP-метода.

### Слой обработки запросов

Servlet-классы инкапсулируют отдельные сценарии приложения. Такой подход позволяет не смешивать разбор HTTP-запроса, маршрутизацию и предметную логику.

Для передачи данных между компонентами используются отдельные классы `Request` и `Response`.

### Работа с базой данных

Работа с PostgreSQL вынесена в пакет `database`. Инициализация БД выполняется приложением автоматически.

Для SQL-запросов используется JDBC и параметризованные запросы.

## Структура проекта

```text
src/main/java/web/
├── database/      # работа с PostgreSQL и инициализация БД
├── entities/      # предметные сущности
├── requests/      # представление HTTP-запросов
├── responses/     # формирование HTTP-ответов
├── servlets/      # обработчики прикладных сценариев
├── Main.java
├── Server.java
├── RequestHandler.java
└── RequestDispatcher.java
```

## Запуск

### Через Maven

Убедитесь, что установлены Java и Maven, а PostgreSQL доступен приложению.

```bash
mvn clean package
java -jar target/*.jar
```

### Через Docker Compose

```bash
docker compose up --build
```

Docker Compose поднимает приложение и PostgreSQL в отдельных контейнерах.
